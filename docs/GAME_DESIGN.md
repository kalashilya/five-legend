# ГЛАВНАЯ ИНСТРУКЦИЯ ПРОЕКТА — «ПЯТЁРКА ЛЕГЕНД»
## Техническое задание на развитие существующей браузерной игры

Ты работаешь над уже существующим проектом «Пятёрка Легенд» — коллекционной карточной игрой по CS2 с управлением собственной командой, тактическими матчами, карточками профессиональных игроков, кейсами, экономикой, лигами и прогрессией.

Твоя задача — не написать новую игру с нуля, а **постепенно превратить уже реализованный проект в полноценную игру, используя существующий код, архитектуру, данные и готовые механики**.

Этот документ содержит согласованные игровые правила и направление развития проекта. Считай их основным техническим заданием.

# 1. КАК ТЫ ДОЛЖЕН РАБОТАТЬ С ПРОЕКТОМ

Это обязательные правила разработки.

### 1.1. Сначала изучение, потом изменения

Перед началом работы:

1. Изучи все существующие файлы проекта.
2. Разберись в архитектуре, взаимосвязях между модулями и хранении прогресса.
3. Проверь, какие механики уже реализованы.
4. Сопоставь существующий функционал с этим техническим заданием.
5. Определи, что работает правильно, что работает частично, чего не хватает и что необходимо исправить.

Не переписывай работающий функционал только потому, что тебе хочется реализовать его другим способом.

### 1.2. Не ломай существующую игру

Запрещается без необходимости:

- Переписывать проект с нуля.
- Удалять существующие игровые механики.
- Менять уже работающие формулы без проверки.
- Сбрасывать сохранения пользователей.
- Менять формат сохранения прогресса без миграции.
- Удалять существующие карточки, команды, фотографии и данные.
- Создавать дублирующие системы, если аналогичная уже существует.

Сохраняй совместимость с текущими сохранениями localStorage.

Если меняется структура сохранения, реализуй безопасную миграцию старых данных.

### 1.3. Принцип реализации

Работай небольшими последовательными этапами:

1. Аудит.
2. План изменений.
3. Реализация.
4. Проверка.
5. Исправление ошибок.
6. Сборка.
7. Отчёт о результате.

Не пытайся одновременно переписать все игровые системы.

Если задача большая, разбивай её на логические части, но доводи каждую часть до рабочего состояния.

### 1.4. Не придумывай правила

В документе есть утверждённые механики и вопросы, по которым ещё не принято окончательное решение.

Если точная формула, цена, вероятность или правило не определены:

- Не выдавай собственное предположение за утверждённое решение.
- Сначала изучи существующую реализацию.
- Предложи конкретный вариант.
- Объясни последствия для баланса.
- Запроси моё решение, если изменение влияет на игровую экономику или фундаментальные механики.

Не нужно спрашивать разрешение на каждую мелочь программирования. Самостоятельно выбирай технические решения, если они не меняют согласованный игровой дизайн.

# 2. ТЕХНОЛОГИИ И СТРУКТУРА ПРОЕКТА

Игра представляет собой браузерное приложение.

Основной технологический стек:

- HTML.
- CSS.
- JavaScript ES2020.
- Без тяжёлых игровых движков.
- Без обязательного сервера для запуска офлайн-версии.
- Canvas допускается для отдельных эффектов, например частиц при открытии кейсов.

Текущая структура проекта:

- `pyaterka-legend-offline.html` — готовая автономная сборка.
- `head.html` — HTML-разметка, стили и оформление.
- `data.js` — команды и база игроков.
- `core.js` — игровая логика, карточки, экономика, матчи и прогресс.
- `ui.js` — интерфейс, анимации, кейсы, матчи, фотографии и звук.
- `photos/` — фотографии игроков.
- `gen.js` — генератор базы игроков.
- `teams.txt` — исходная информация о командах и составах.
- `test.js` — проверка игровой логики и баланса.
- `build.sh` — сборка автономного HTML-файла.

Правила:

1. Не редактируй вручную сгенерированный `data.js`, если изменение относится к исходным данным.
2. Используй `teams.txt` и `gen.js` для формирования базы.
3. После изменения исходников запускай `build.sh`.
4. Не редактируй готовый автономный HTML вместо исходных файлов.
5. Не создавай альтернативную архитектуру без необходимости.
6. Проверяй работоспособность после каждого крупного изменения.

Текущий проект уже содержит примерно 500 карточек игроков, 101 команду, особые версии карточек, кейсы, коллекцию, состав, экономику и матчевую систему.

Сохрани существующие данные и расширяй их.

# 3. КОНЦЕПЦИЯ ИГРЫ

«Пятёрка Легенд» — коллекционная карточная игра по Counter-Strike 2.

Основной игровой цикл:

1. Игрок получает карточки профессиональных игроков.
2. Собирает собственную пятёрку.
3. Назначает игроков на подходящие роли.
4. Выбирает капитана.
5. Формирует тактическую колоду.
6. Играет рейтинговые матчи против AI.
7. Получает монеты, опыт, кубки и награды.
8. Открывает кейсы.
9. Улучшает карточки.
10. Расширяет коллекцию.
11. Поднимается по лигам.
12. Участвует в сезонных соревнованиях.

Главная особенность игры — сочетание коллекционирования карточек и тактического управления командой.

Матчи не должны быть обычным случайным розыгрышем победителя. Решения игрока, состав, способности, экономика и тактика должны действительно влиять на результат.

# 4. БАЗА ПРОФЕССИОНАЛЬНЫХ ИГРОКОВ И HLTV

Это одно из самых важных требований проекта.

## 4.1. Достоверность статистики

Все характеристики и статистические показатели реальных игроков должны основываться на данных HLTV.

**Запрещено генерировать реальные показатели игроков случайным образом.**

Нельзя просто назначать игроку случайные значения стрельбы, стабильности, интеллекта или других характеристик.

Случайность допустима:
- При симуляции матчей.
- При выборе выпадающих карточек.
- При определении случайных игровых событий.
- В других специально предусмотренных игровых механиках.

Но не при создании исходной статистики реального профессионального игрока.

## 4.2. Источники статистики

При оценке игрока используй:

- Последние 12 месяцев — основная статистическая база.
- Последние 3 месяца — текущая форма.
- Карьеру игрока — дополнительный исторический контекст.

Характеристики должны отражать реальные особенности игрока.

Не путай реальные показатели HLTV с игровыми характеристиками, которые рассчитываются на их основе.

## 4.3. Рейтинг карточки

В проекте используется общий рейтинг OVR и шесть характеристик.

Необходимо проверить существующую систему расчёта и разработать прозрачную связь между статистикой HLTV и игровыми показателями.

Нельзя допускать, чтобы рейтинг был случайным или не соответствовал реальному уровню игрока.

Если для расчёта необходимы новые формулы, сначала предложи их и согласуй со мной.

## 4.4. Индивидуальные способности

Каждая карточка имеет две способности:

1. Базовая способность, связанная с естественной ролью.
2. Индивидуальная способность, связанная с конкретным профессиональным игроком.

Индивидуальная способность должна отражать реальный стиль игрока, подтверждённый статистикой и особенностями его игры.

Топ-20 игроков требуют особенно детальной проработки.

Для остальных допускаются более простые и нейтральные способности, если нет достаточных оснований для уникальной механики.

Не придумывай игрокам вымышленные достижения и игровые особенности.

## 4.5. Обновление базы

База обновляется после крупных турниров:

- Major.
- BLAST.
- IEM.
- Другие крупные профессиональные соревнования.

Изменения статистики и формы учитываются при обновлении базы, а не происходят случайным образом каждый день.

# 5. КАРТОЧКИ ИГРОКОВ

## 5.1. Основная информация

Карточка должна содержать:

- Фотографию игрока.
- Ник.
- Команду.
- Общий рейтинг OVR.
- Естественную роль.
- Редкость.
- Уровень прокачки.
- Шесть характеристик.
- Две способности.

При просмотре карточки должна открываться расширенная информация.

## 5.2. Редкости

В игре используются:

1. Ширпотреб.
2. Армейское.
3. Запрещённое.
4. Засекреченное.
5. Тайное.

Каждая редкость получает собственное оформление:

- Цвет.
- Фон.
- Рамку.
- Визуальные эффекты.
- Отличительный стиль.

Редкости должны хорошо различаться между собой.

## 5.3. Прокачка

Максимальный уровень карточки — 5.

При прокачке автоматически усиливаются:

- Общий рейтинг.
- Шесть характеристик.
- Базовая способность.
- Индивидуальная способность.

Отдельный выбор характеристик или распределение очков не требуется.

При просмотре улучшения игрок должен видеть, какие именно показатели изменятся.

На пятом уровне карточка получает золотое или элитное оформление.

Прокачка не должна полностью возвращать затраченные ресурсы при последующей продаже.

## 5.4. Особые версии

Существуют специальные версии:

- Игрок недели.
- MVP.
- Другие предусмотренные проектом специальные карточки.

Особые версии получают:

- Уникальное оформление.
- Улучшенные характеристики.
- Усиленные способности.
- Уникальную версию индивидуальной способности.

Они должны ощущаться как действительно ценные карточки, а не просто обычные карточки с другой рамкой.

## 5.5. Исторические версии

Один профессиональный игрок может иметь несколько отдельных карточек для разных команд и периодов карьеры.

Например:

- Игрок в NAVI.
- Тот же игрок после перехода в другую команду.

Это разные коллекционные карточки.

Характеристики исторических версий должны соответствовать статистике соответствующего периода.

При трансфере:

- Старая карточка сохраняется.
- Её команда не меняется.
- Прокачка старой версии сохраняется.
- После обновления базы появляется новая версия игрока.

## 5.6. Продажа карточек

Продать можно любую карточку.

Отдельной системы блокировки карточек от продажи нет.

При продаже последней копии важной карточки, например игрока активного состава, необходимо дополнительное подтверждение.

То же правило действует для последней копии особой версии.

Цена продажи зависит от:

- Редкости.
- Рейтинга игрока.
- Уровня прокачки.

Продажа предназначена преимущественно для избавления от ненужных карточек, а не для основного заработка монет.

# 6. РОЛИ И СОСТАВ

Основная команда состоит из пяти игроков.

Роли:

1. IGL — капитан.
2. AWP — снайпер.
3. ENTRY — энтри.
4. SUP — саппорт.
5. LURK — люркер.

## 6.1. Естественные роли

Естественная роль игрока закреплена за карточкой.

Изменить или переобучить её нельзя.

Игрок может занимать другой слот, но получает штраф эффективности −5.

Роль должна влиять на реальное поведение игрока в матче, а не быть просто надписью.

## 6.2. Капитан

Капитаном может быть только игрок с естественной ролью IGL.

Капитан влияет на:

- Тактические решения.
- Разведку.
- Командный импульс.
- Управление командой.

Игрок самостоятельно назначает капитана среди подходящих IGL.

Игра дополнительно рекомендует наиболее подходящего кандидата.

Играть без капитана разрешено, но команда теряет соответствующие бонусы.

## 6.3. Сохранённые составы

Игрок может сохранять до трёх разных пятёрок.

Можно переключаться между ними перед матчем.

Во время матча состав менять запрещено.

## 6.4. Химия

Система сыгранности зависит от совместимости карточек:

- Общая команда.
- Совместимость ролей.

Химия не растёт от количества сыгранных матчей или времени.

В интерфейсе необходимо отображать:

- Общую химию пятёрки.
- Индивидуальную совместимость игроков.

## 6.5. Сравнение карточек

Добавить возможность сравнивать две карточки рядом:

- OVR.
- Шесть характеристик.
- Базовая способность.
- Индивидуальная способность.

Сравнение должно быть понятным и удобным.

# 7. МАТЧЕВАЯ СИСТЕМА

Это центральная игровая механика.

Матч должен быть тактическим, последовательным и достаточно непредсказуемым.

## 7.1. Формат матча

Утверждённые правила:

- Матч проходит до 13 побед.
- Смена сторон после 12 раундов.
- При счёте 12:12 играется решающий раунд.
- Перед матчем происходит выбор карты через бан одной из трёх предложенных карт.

Проверь существующую реализацию и сохрани уже работающие механики.

## 7.2. Экономика раундов

В проекте предусмотрены:

- Пистолетные раунды.
- Полная закупка — 4000.
- Форс-закупка — 2500.
- Эко.
- Бонус за серию побед — +1.5.
- Стартовые деньги — 800.
- Максимальные деньги — 12000.

Не меняй значения без отдельного согласования.

Закупка должна влиять на силу команды и исход раунда.

## 7.3. Управление раундом

Игрок принимает решения перед каждым раундом.

Утверждено:

- Своя колода тактических карт.
- Случайный добор карт из собственной колоды.
- Возможность использовать несколько приказов за раунд, пока хватает импульса.
- Частичная разведка.
- Автоматическая симуляция раунда.
- Лента ключевых событий.

## 7.4. Тактическое управление

Используется комбинированная система:

- Готовые тактические планы.
- Возможность изменить направление атаки.
- Регулировка темпа.
- Приоритеты отдельных ролей.
- Дополнительные настройки перед раундом.

Игрок не должен быть ограничен одной кнопкой «Атаковать».

Тактика должна менять поведение команды, а не просто прибавлять фиксированные очки к OVR.

## 7.5. Тактические карты

Уже предусмотрена система тактических карт с импульсом.

Существующая схема содержит:

- Максимум 8 импульса.
- +2 импульса за раунд.
- Колоду из 10 карт.
- Стартовую руку.
- Стоимость отдельных приказов.

Сначала проведи аудит текущих правил.

Карты должны иметь различные назначения:

- Командные.
- Ролевые.
- Ситуативные.
- Обманные.
- Контрмеры.

Каждая карта должна иметь понятное условие применения и реальное влияние на поведение команды.

## 7.6. AI соперника

AI должен учитывать:

- Состав игрока.
- Роли.
- Способности.
- Тактические решения.
- Экономику.
- Карту.
- Предыдущие действия игрока.
- Слабые места противника.

AI должен адаптироваться к истории матчей и менять стиль игры.

Он может использовать обманные действия и менять привычное поведение.

Но AI не должен знать абсолютно всё о действиях игрока.

## 7.7. Уровни ошибок AI

Частота и качество ошибок зависят от уровня соперника.

- Слабые соперники чаще совершают ошибки и выбирают плохие решения.
- Средние соперники чередуют хорошие и плохие решения.
- Сильные соперники ошибаются редко.
- Топовые соперники действуют почти профессионально.

При этом даже топовый AI не должен быть непобедимым.

Не используй искусственную помощь слабой команде для создания напряжения.

## 7.8. Информация о сопернике

Перед матчем игрок видит только:

- Общий OVR.
- Лигу.
- Количество кубков или рейтинг.

Полный состав, способности и тактики заранее не раскрываются.

## 7.9. Карты CS2 и индивидуальные способности

Индивидуальные способности игроков могут получать ситуационные бонусы на подходящих картах.

Бонусы основываются на реальном стиле игрока.

Не нужно вводить отдельную чрезмерно сложную систему предпочтительных позиций.

## 7.10. Экран матча

Используй комбинированный интерфейс:

- Тактическая мини-карта.
- Лента событий.
- Текущий счёт.
- Экономика.
- Краткие показатели игроков.

Экран должен быть лёгким и удобным на мобильных устройствах.

Используй CSS, простые индикаторы и минимальную графику.

Не создавай тяжёлую 3D-сцену.

## 7.11. Послематчевый отчёт

После матча игрок получает:

- Итоговый счёт.
- Победу или поражение.
- Убийства и смерти каждого игрока.
- Количество MVP.
- Экономику команды.
- Вклад каждого игрока.
- 2–3 ключевых момента.
- Краткие выводы о том, что получилось и что стоило изменить.

Не нужно создавать огромный аналитический отчёт.

# 8. КЕЙСЫ И ОТКРЫТИЕ КАРТОЧЕК

Кейсы должны быть одним из самых привлекательных элементов игры.

Обычное открытие в стиле стандартной рулетки CS не является желаемым направлением.

Нужно развивать уникальную анимацию материализации карточки.

## 8.1. Существующие кейсы

| Кейс | Цена |
|---|---:|
| Базовый | 400 монет |
| Про | 1200 монет |
| Элитный | 4000 монет |

В одном кейсе находится пять карточек.

Бесплатный базовый кейс доступен один раз в сутки.

Обновление происходит в фиксированное время, а не по скользящему интервалу в 20 часов.

Точное время обновления ещё необходимо определить.

## 8.2. Обычное открытие

Предпочтительная концепция — голографический сканер.

Последовательность:

1. Кейс появляется на экране.
2. Начинается открытие.
3. Появляется голографический сканер.
4. Формируется силуэт игрока.
5. Сканируются характеристики.
6. Определяется команда и роль.
7. Карточка материализуется из частиц и голографических элементов.

Предлагаемая длительность — 3–5 секунд.

Это ориентир, а не обязательная цифра.

## 8.3. Редкое выпадение

Если вероятность конкретной карточки в конкретном кейсе ниже 5%, можно использовать специальную анимацию:

1. Сканер.
2. Глитч.
3. Затемнение и тишина.
4. Надпись «Обнаружен редкий игрок».
5. Появление арены.
6. Прожекторы и дым.
7. Выход игрока.
8. Демонстрация карточки.

Предлагаемая длительность — 7–10 секунд.

Разные арены:

- Cyber Arena.
- Championship Arena.
- Underground Arena.
- World Finals.

Цвета и оформление должны учитывать команду игрока.

## 8.4. Особые карточки

Для MVP и «Игрока недели» предусматривай возможность индивидуальных анимаций.

Анимации должны отличаться от обычного открытия.

Не превращай каждое открытие в одинаковый ролик.

## 8.5. Производительность

Не используй тяжёлые видео и большие фоновые изображения.

Предпочтительно:

- CSS-анимации.
- SVG.
- Небольшие Canvas-эффекты.
- Оптимизированные изображения.
- Частицы только в нужные моменты.

Анимация должна быть красивой, но не должна тормозить игру.

## 9.1. Получение монет

## 9.2. Награды за матчи

Продажа карточек даёт небольшую часть их стоимости.

# 10. TRADE-UP КОНТРАКТЫ

Контракт — способ обменять десять карточек на одну новую.

Утверждённые правила:

1. Необходимо 10 обычных карточек одной редкости.
2. Команды можно смешивать.
3. Особые версии запрещены.
4. На выходе всегда одна карточка.
5. Получить монеты вместо карточки нельзя.

Возможны два результата:

- Карточка следующей редкости, в том числе с низким рейтингом.
- Карточка той же редкости, но с более высоким рейтингом.

Средний рейтинг вложенных карточек влияет на шанс более сильного результата.

Однако высокий средний рейтинг не гарантирует его.

Дополнительные правила:

- Карточку из контракта можно использовать в следующем контракте, если она обычная и подходит по редкости.
- История контрактов не сохраняется.
- До подтверждения игрок видит все 10 карточек.
- Отображается средний рейтинг.
- Показываются приблизительные диапазоны вероятностей двух исходов, без точных процентов.
- До запуска можно менять и удалять карточки.
- После запуска отменить контракт нельзя.
- Нельзя отменять анимацию для повторного получения результата.

Точные вероятности и формулу расчёта необходимо согласовать отдельно.

Максимальная редкость «Тайное» требует отдельного решения, поскольку следующей редкости уже нет.

# 11. ЗАДАНИЯ И ЕЖЕДНЕВНАЯ АКТИВНОСТЬ

В игре должна существовать полноценная система заданий.

## 11.1. Количество

- 4 ежедневных задания.
- 5 недельных испытаний.
- 1 специальное задание на 7 дней одновременно.

## 11.2. Обновление

Ежедневные задания обновляются ежедневно.

Недельные — один раз в неделю.

Специальное задание — через 7 дней.

Все невыполненные задания сгорают.

Прогресс не переносится.

## 11.3. Время

Обновление ежедневных и недельных заданий происходит в 00:00 по Москве (UTC+3).

День начала недельного цикла ещё необходимо определить.

## 11.4. Получение награды

Все награды забираются вручную кнопкой «Забрать награду».

Если задание выполнено, но награда не забрана, она сохраняется бессрочно до получения.

## 11.5. Награды

- Ежедневные — преимущественно монеты.
- Недельные — кейсы и ценные ресурсы.
- Специальные — редкие и эксклюзивные награды.

Прямые карточки игроков выдаются только за главное недельное и специальное задание.

При получении карточной награды игрок выбирает одну из трёх предложенных карточек.

Все три принадлежат пулу текущей лиги.

Дубликаты разрешены.

Нельзя перегенерировать предложения, отказаться или пропустить выбор.

## 11.6. Требования к заданиям

- Ежедневные задания простые, без сложных требований к ролям.
- Недельные и специальные могут содержать требования к ролям и составу.
- Ежедневные преимущественно требуют участия и действий, а не побед.
- Недельные сочетают участие и победы.
- Специальные требуют побед и могут включать сложные условия.

Одно действие или матч может продвигать сразу несколько подходящих заданий.

## 11.7. Рейтинговые матчи

Все задания засчитываются только в рейтинговых матчах.

Если игрок досрочно выходит:

- Фактические убийства и сыгранные раунды засчитываются.
- Победа и завершение матча не засчитываются.

## 11.8. Генерация заданий

Задания формируются случайно из подготовленных пулов с учётом лиги.

Однако генератор обязан учитывать коллекцию и выдавать только выполнимые задания.

Если игрок продал необходимую карточку после выдачи задания, задание не меняется. Игрок должен снова получить подходящую карточку.

Прокачка не меняет идентичность карточки.

Особые версии учитываются согласно конкретным условиям задания.

Для задания на игрока достаточно одной копии.

Сложность и награда определяются лигой, а не размером коллекции или статистикой игрока.

Задания не адаптируются к серии побед и поражений.

# 12. ЛИГИ И КУБКИ

## 12.1. Рейтинговая система

Утверждённые изменения рейтинга:

- Обычная победа — +25.
- Уверенная победа с разницей больше 5 раундов — +30.
- Победа 13:0 — +30.
- Обычное поражение — −25.
- Поражение 0:13 — −30.

Бонусы не складываются.

Максимальная награда за победу — +30.

При разнице ровно 5 раундов действует обычная награда.

## 12.2. Подбор соперника

Ориентир подбора — примерно ±100 рейтинговых очков.

Учитывай рейтинг команды и состав соперника.

## 12.3. Лиги

Лига пересчитывается сразу после изменения рейтинга.

Понижение разрешено.

При приближении к нижней границе лиги игрок получает предупреждение.

Защиты от понижения нет.

Количество лиг — 7.

Точные пороги необходимо сверить с существующим кодом и согласовать.

## 12.4. Сезоны

Сезон длится один месяц.

После его окончания происходит частичный сброс рейтинга.

Чем выше лига, тем больше очков теряет игрок.

Точные значения ещё не определены.

## 12.5. Сезонные награды

Игрок получает:

- Монеты.
- Кейсы.
- Эксклюзивное оформление профиля.

Эксклюзивные карточки игроков за сезон пока не вводить.

## 12.6. Таблицы лидеров

Должны существовать:

- Общая глобальная таблица.
- Отдельная таблица каждой лиги.

## 12.7. История сезонов

Сохранять:

- Финальную лигу.
- Итоговое место.
- Финальный рейтинг.

Полную историю всех матчей и составов за прошлые сезоны пока не требуется сохранять.

## 12.8. Сезонные задания

Несколько дополнительных целей на весь месячный сезон.

Не создавать отдельную многоуровневую сезонную шкалу прогресса.
